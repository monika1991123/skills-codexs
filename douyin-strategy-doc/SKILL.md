# 抖音交易策略文档提取

把视频中的交易方法复原为可检查的 Markdown。重点是忠实和可复现，不替视频补造参数。

## 输入与输出

输入可以是：

- 抖音短链或完整分享口令；
- 哔哩哔哩视频 URL/BV 号；
- 其他可访问的视频链接；
- 用户指定的输出目录或范例文档。

默认把文档写到当前工作目录，文件名为 `<策略标题>_视频整理.md`。如果用户指定目录或文件名，优先服从。

## 工作流

### 1. 读取本地约束

读取当前目录适用的 `AGENTS.md`。若属于长期交易项目或涉及策略实现，按项目规则读取 `agent_memory/`；单次视频整理不新建项目 memory。

### 2. 获取视频与元数据

1. 保留原始分享链接、视频标题、作者、平台、视频 ID 和访问时间（UTC+8）。
2. 先运行：

   ```bash
   python3 <skill-dir>/scripts/fetch_video.py '<URL>' --output-dir /tmp/strategy-video
   ```

3. 如果抖音反爬导致失败：
   - 用 `curl -L -D -` 解析短链，记录最终 URL 和 `aweme_id`；
   - 搜索精确标题或 `aweme_id`，优先寻找作者转载或同源哔哩哔哩视频；
   - 找到 BV 号后再次运行 `fetch_video.py`；
   - 不把标题相似但内容未核对的视频当成同源。
4. 不绕过登录、付费、验证码或访问控制。拿不到视频时说明阻塞，不伪造整理结果。

### 3. 提取音频、画面和转写

视频下载后运行：

```bash
python3 <skill-dir>/scripts/prepare_media.py /tmp/strategy-video/video.mp4 \
  --output-dir /tmp/strategy-video/analysis
```

该脚本生成：

- `audio.wav`：16 kHz 单声道音频；
- `frames/`：定时抽帧；
- `contact-sheet.jpg`：关键画面总览；
- `transcript.*`：本机存在 Whisper 时生成的中文转写。

至少同时检查转写和关键画面。自动转写会误识别“上穿/下穿、止损/止盈、均线周期、百分比”等交易术语，关键规则必须用画面字幕校正。

### 4. 分层记录证据

把内容分成三类：

1. **视频明确披露**：可直接写为原始规则。
2. **可从画面可靠推导**：标注“根据画面推导”。
3. **视频未披露**：列为缺失参数，不自行填充。

视频中的收益率、胜率、回测提升等宣传数据，如果没有品种、区间、费用和逐笔账本，只能写成“视频声称”，不能写成已验证事实。

### 5. 生成文档

使用 `assets/strategy-doc-template.md` 的结构。按视频实际内容删掉无关小节，不为凑结构添加空话。

量化定义和视频原文必须分开：

- “视频规则”忠实复原；
- “最小可回测定义”可以提出 SMA/EMA、收盘确认、下一根开盘成交等默认值，但明确这些是实现建议；
- 资金管理、手续费、滑点、资金费率和同根 K 线冲突必须纳入回测要求；
- 默认只做研究、回测和模拟，不触发真实交易。

### 6. 验证

写完后执行：

```bash
test -s '<output.md>'
rg -n '^#|视频未|未披露|回测|风险|资金' '<output.md>'
```

再回读全文，检查：

- 多空是否对称且没有方向写反；
- 数字、周期和百分比是否与视频一致；
- 是否把推测误写成视频事实；
- 是否记录来源链接和 UTC+8 时间；
- 是否给出资金口径和可验证条件。

若项目 memory 适用，记录新增文档和仍未解决的参数缺口。

## 失败边界

- 只能获得标题、搜索摘要或几张缩略图时，不声称“看完视频”。
- 找到转载视频时，在文档中同时记录原始链接和转载链接。
- 无音轨、无字幕或画面模糊时，列出能确认和不能确认的内容。
- 下载器失败后优先使用公开平台 API 或同源转载；不反复盲试同一命令。

## 最终回复

只需给出：

1. 文档绝对路径链接；
2. 已核对的核心规则一句话摘要；
3. 无法复原的关键参数；
4. 验证证据（例如行数、文件大小或检查结果）。
